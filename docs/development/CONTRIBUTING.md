# 贡献指南

本项目是个人开发仓库，不要求为了形式走 Pull Request 流程。

## 工作流程

1. 明确要解决的问题和验收标准。
2. 从本地 `main` 建立临时功能分支；不要为功能分支创建远程分支。
3. 保持数据、UI 和工作流改动边界清晰。
4. 同步增加或更新测试。
5. 运行相关质量门禁，并检查实际 diff。
6. 向用户报告改动文件、测试证据、剩余风险和拟用提交信息。
7. 按 `AGENTS.md` 的授权门禁，等待用户明确确认后再提交。
8. 将功能分支快进合并到本地 `main`，只推送 `main`，不创建 Pull Request。
9. 合并完成后删除功能和远程临时分支，保持 `origin` 只有 `main`。

## 提交前检查清单

- 没有手工修改受保护的历史开奖记录。
- Schema 和数据门禁通过。
- 桌面端和移动端浏览器测试通过。
- 浅色和深色已完成真实浏览器检查，截图不提交。
- Axe 无障碍检查没有严重或致命问题。
- README 和架构文档与实际项目一致。
- 不提交密钥、本地缓存或生成物。

## 提交信息风格

使用简洁、明确的提交前缀：

- `feat:`
- `fix:`
- `refactor:`
- `test:`
- `docs:`
- `chore(data):`
- `ci:`
