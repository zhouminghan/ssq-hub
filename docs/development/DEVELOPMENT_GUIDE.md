# Development Guide

## Frontend Work

1. Start `npm run dev`.
2. Change the smallest relevant ES module or CSS file.
3. Run `npm run typecheck`, `npm run lint`, and `npm run test:unit`.
4. Run the relevant Playwright test.
5. Inspect desktop and mobile screenshots for layout regressions.

Do not add a runtime dependency unless an ADR explains why native browser
capability is insufficient.

## Adding a Data Field

1. Update `scripts/schema.py` validation.
2. Update the relevant JSON Schema under `schemas/`.
3. Update `calc_all.py` and `manifest.py`.
4. Update `verify_data.py`.
5. Add a Python unit test and schema fixture if appropriate.
6. Update browser types/consumers.
7. Recompute and run all data gates.

## Adding a UI Capability

1. Add a Playwright assertion that fails before implementation.
2. Implement against existing tokens and module boundaries.
3. Add keyboard and screen-reader behavior.
4. Verify at 1440, 1280, 768, 390, and 375.
5. Verify light, dark, and auto.
6. Update the capability reconciliation report.

`requirements.lock` includes the Ruff version used by CI.

## Data Changes

Never manually edit historical records. Use the pipeline. Normal runs only add
new issues. Historical corrections require explicit approval and a complete
correction ledger.

## Formatting

- JavaScript: two spaces, single quotes, semicolons.
- CSS: two spaces, one component file, responsive overrides separate.
- Python: Ruff defaults, four spaces, type hints where they clarify contracts.
- JSON: generated by scripts with two-space indentation.
