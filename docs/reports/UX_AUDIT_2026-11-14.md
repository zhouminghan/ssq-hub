# UI/UX Audit and Rework

Date: 2026-11-14

Scope: trend view, insights view, filters, theme menu, profile drawer, loading,
CDN fallback, browser cache, network failure, five viewport widths, light/dark
themes.

## Findings and Resolution

| Priority | Finding | Resolution |
|---|---|---|
| P1 | Light mode mixed cool grey, pink and beige surfaces, weakening red/blue data semantics | Rebuilt light tokens around neutral canvas/content/tool surfaces; red/blue are reserved for ball data and gold is limited to recent-five emphasis |
| P1 | 375px filter bar clipped Custom and Reset behind hidden horizontal scrolling | Replaced with explicit two-row mobile layout; Custom, Reset, range select and theme target remain inside viewport |
| P2 | CDN fallback still looked like a fresh primary source | Status now shows `备用镜像` and `本次已切换备用` |
| P2 | Cache time was only in a tooltip | Cache status now visibly shows `本地缓存` and cache time |
| P2 | Network failure had conflicting loading and duplicated error copy | Dashboard changes to `数据不可用`; the main error is a concise user-facing retry message |
| P2 | Profile close target and frequency values were too small/cramped | Close target is 42px; frequency values use a non-wrapping 132px column; bar meaning has a text legend |
| P2 | Mobile touch targets were undersized | Header actions, tabs, selects, reset, menu items and other primary controls are 40px or larger |
| P2 | Critical 9–10px text strained readability | Omission values, chart values and key profile numbers are raised; secondary metadata remains compact |
| P2 | Insights grid left a large blank area under the short card | Desktop now uses a 7/5 and 5/7 offset layout with balanced row heights |

## Verified Layout

- 1440 / 1280 / 768 / 390 / 375 widths.
- Light and dark themes.
- No page-level horizontal overflow.
- 375px Custom and Reset controls remain fully inside the viewport.
- Profile close target: 42×42px.
- Profile frequency value has `scrollWidth == clientWidth`.
- Desktop insights row heights align rather than leaving a 200px void.

## Remaining Product Opportunities

- Pixel visual baselines run locally on macOS Chrome and are intentionally skipped
  in CI because Linux font rendering differs.
- Full-history mode creates about 448k DOM nodes; row virtualization is the next
  performance investment if full-history scanning becomes primary.
- Firefox behavior remains an environment/CI verification item.
- The next-draw label is an estimate based on the weekly schedule and configured
  official pause windows.

## Original Color Semantics Restored

After comparing against the live pre-reconstruction site, the table's original
data color language was restored:

- Big / odd / prime structure characters use the red semantic color.
- Small / even / composite characters use the blue semantic color.
- The auxiliary block keeps a restrained warm surface and amber header accent.
- Red and blue balls use radial highlight gradients again, with base colors
  selected to retain readable text contrast in light and dark themes.
- GitHub and theme controls are icon-only at the top right; their Chinese labels
  remain only in accessible names.
- The cloned sticky header no longer paints a second `期号`; the fixed issue
  overlay owns that label and the table header ignores text-selection drags.
- The table no longer creates an outer stacking context, so the frozen issue
  column sits above the SVG blue-ball path during horizontal scrolling.
